# PathMaster

*[English](README.md) · Українська*

PathMaster редагує змінну `PATH` у Windows — перелік тек, у яких Windows шукає програму, коли ви
вводите команду. Він показує ваш `PATH` і `PATH` комп'ютера як звичайні списки, які можна читати,
переставляти й виправляти, повідомляє, які записи зіпсовані та чому, і зберігає копію списку перед
тим, як його змінити. Його зроблено насамперед для користувача програми екранного доступу, і це
один портативний виконуваний файл, який тримає все, що записує, у теці поруч із собою.

## Доступність

Це та частина PathMaster, яка не є функцією. Усе інше вирішувалося після неї.

- **NVDA — програма екранного доступу, з якою його перевіряють.** Кожен випуск проходить ручну
  перевірку з NVDA — див. [Як перевіряються випуски](#як-перевіряються-випуски).
- **JAWS і «Оповідач» не зламано навмисно, але й не перевірено.** PathMaster використовує
  стандартні елементи керування Windows і взагалі не робить власних викликів доступності, тож усе,
  що читає звичайний список і звичайне меню, має читати й цю програму. Ніхто цього не вимірював.
- **Ніщо не існує лише як звук.** Кожне повідомлення, яке програма промовляє, водночас показано в
  одному рядку повідомлень над вкладками. Ніде не задано жодного кольору, тож режим високої
  контрастності працює — просто немає чому крізь нього пробиватися.
- **Кожна дія має шлях із клавіатури й місце в меню.** Жоден сценарій не потребує миші — див.
  [мапу клавіатури](#клавіатура).
- **Проблеми запису читаються як частина рядка.** Коли ви переходите стрілками на запис, читається
  шлях, а далі — лише якщо із записом щось не так — «Стан: » і слова, що називають проблему.

### Якщо NVDA замовкає на списку

Є один відомий стан — трапився одного разу й жодного разу не відтворився — у якому NVDA сприймає
список як єдиний об'єкт і нічого не промовляє, коли ви йдете по ньому стрілками. PathMaster наразі
не вміє його виявляти, і поки він триває, рядок промовлюваних повідомлень майже напевно теж
мовчить.

**Перевірити його можна так:** станьте на рядок у списку й натисніть `NVDA+Tab`. NVDA має
відповісти назвою **рядка** («елемент списку»). Якщо вона відповідає назвою списку — ви в цьому
стані.

**Як із нього вийти, по порядку:**

1. `Alt+Tab` до іншого вікна й назад.
2. Закрити PathMaster і запустити знову.
3. Перезапустити NVDA. Це допомагає завжди.

Жоден із цих кроків нічого не втрачає, крім незбережених змін, а про них PathMaster питає, перш
ніж їх відкинути.

### Вікно адміністратора потребує встановленої NVDA

Щоб редагувати `PATH` комп'ютера, потрібні права адміністратора, і PathMaster отримує їх,
перезапускаючи себе (Інструменти → Перезапустити від імені адміністратора). **Портативна NVDA не
може читати те вікно** — Windows їй цього не дозволяє, — тож користуйтеся встановленою NVDA, якщо
вам потрібно редагувати `PATH` системи.

## Встановлення

### winget

```powershell
winget install RuslanIskov.PathMaster
```

### scoop

```powershell
scoop bucket add ruslan-rv-ua https://github.com/ruslan-rv-ua/scoop-bucket
scoop install pathmaster
```

### Пряме завантаження

Візьміть `PathMaster-v<версія>-x64.exe` і файл `.sha256` поруч із ним на
[сторінці випусків](https://github.com/ruslan-rv-ua/pathmaster2/releases). Немає ні архіву, який
треба розпаковувати, ні інсталятора, який треба запускати: `.exe` — це і є вся програма.
Покладіть його там, де він має жити, — теку `data` він створить поруч із собою сам.

#### Windows покаже попередження, і це очікувано

PathMaster **не підписано цифровим підписом**. Підпис коштує грошей щороку й починає щось важити
лише після того, як достатньо людей встановили підписаний файл, тож його свідомо відкладено доти,
доки в цієї програми не буде користувачів, заради яких варто морочитися. Через це SmartScreen під
час першого запуску показує «Windows захистила ваш ПК». Оберіть **Докладніше**, а потім
**Виконати в будь-якому разі**.

Це попередження означає «за цей файл ніхто не поручився», а не «цей файл зіпсований» — тож ось як
перевірити файл самостійно.

#### Перевірте те, що завантажили

Файл `.sha256`, опублікований поруч із кожним випуском, містить точний відбиток `.exe` цього
випуску. Порівняйте його з тим файлом, який у вас є:

```powershell
Get-FileHash .\PathMaster-v0.1.0-x64.exe -Algorithm SHA256
Get-Content .\PathMaster-v0.1.0-x64.exe.sha256
```

Довгий шістнадцятковий рядок має бути однаковий в обох. (Великі чи малі літери значення не мають.)
Щоб PowerShell відповів одним словом замість двох рядків:

```powershell
(Get-FileHash .\PathMaster-v0.1.0-x64.exe -Algorithm SHA256).Hash -eq ((Get-Content .\PathMaster-v0.1.0-x64.exe.sha256) -split ' ')[0]
```

`True` означає, що файл побайтово той самий, який було опубліковано. Будь-яка інша відповідь
означає: не запускайте його.

## Клавіатура

Повна мапа. Пункти меню називають власні комбінації, тож програма екранного доступу зачитує їх,
коли ви йдете по меню, — ця таблиця подає ту саму інформацію в одному місці.

| Клавіші | Що робить |
|---|---|
| `Tab` / `Shift+Tab` | Перехід між усіма елементами вкладки, по колу й без пасток |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | Наступна / попередня вкладка: PATH користувача, PATH системи, Резервні копії |
| `↑` `↓` | Рух по списку |
| `F2`, `Enter` або подвійне клацання | Змінити запис, на якому стоїть курсор |
| `Del` | Видалити запис, на якому стоїть курсор, — без підтвердження, бо `Ctrl+Z` його повертає |
| `Alt+↑` / `Alt+↓` | Перемістити запис на одну позицію вгору / вниз |
| `Ctrl+Z` / `Ctrl+Y` | Скасувати / повторити, з повідомленням про те, що саме скасовано |
| `Ctrl+S` | Застосувати — записати цей PATH до реєстру, попередньо зберігши його копію |
| `F5` | Оновити — перечитати цей PATH з реєстру |
| `Alt+F4` | Закрити, спитавши спершу, чи є незбережені зміни |
| `Alt+F` / `Alt+E` / `Alt+T` / `Alt+H` | Відкрити меню Файл / Редагування / Інструменти / Довідка |
| `NVDA+End` | Прочитати рядок стану: кількість записів і проблем та довжину об'єднаного PATH |
| `NVDA+Tab` | Не комбінація PathMaster — перевірка, описана в розділі [Якщо NVDA замовкає](#якщо-nvda-замовкає-на-списку) |

«Застосувати» і «Відхилити зміни» недоступні, поки в списку немає незбережених змін, і кожен пункт
меню читається як недоступний, коли ним не можна скористатися, — саме так програма екранного
доступу вам про це й каже.

## Що і куди записується

PathMaster портативний, і це твердження варто сформулювати точно.

**Сама програма записує у два місця й більше нікуди:**

- `data\` поруч із виконуваним файлом — `settings.json`, `backups\` (збережені копії) і
  `pathmaster.log`. Ніщо з того, що вона записує, не живе деінде, і немає налаштування, яке
  переносило б цю теку.
- Два значення `PATH`, коли ви натискаєте «Застосувати»: `HKCU\Environment` → `Path` для вашого і
  `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment` → `Path` для системного.

**З одним названим винятком.** Кнопка **Огляд** у діалозі додавання/зміни відкриває власний
провідник тек Windows, а Windows записує відвідані теки до власних ключів реєстру «нещодавно
використані» (`HKCU\...\Explorer\ComDlg32`). Це пише операційна система, у цьому процесі, і
PathMaster не може цьому завадити. Якщо ви ніколи не натискаєте «Огляд», цього ніколи й не
відбувається.

**Те, що записують менеджери пакунків, — їхнє, а не наше:**

- **winget** копіює `.exe` до власної теки пакунка в `%LOCALAPPDATA%`, **перейменовує його на
  `pathmaster.exe`**, додає запис у `HKCU`, щоб програма з'явилася в «Програми та компоненти», і
  кладе символічне посилання до своєї теки Links, яка є у вашому `PATH`. Саме так `pathmaster`
  стає командою, яку можна набрати.
  - `winget upgrade` **зберігає** вашу теку `data` разом із налаштуваннями й резервними копіями.
  - `winget uninstall` **видаляє** теку пакунка, а разом із нею й вашу теку `data` — **включно з
    резервними копіями**. Спершу скопіюйте те, що хочете зберегти.
- **scoop** встановлює програму в `~\scoop\apps\pathmaster`, кладе шим у ваш `PATH`, додає ярлик
  до меню «Пуск» і — бо так каже маніфест — переносить вашу теку `data` до
  `~\scoop\persist\pathmaster\data` й повертає її посиланням. Тому ваші налаштування й резервні
  копії переживають `scoop update`.

## Налаштування

`data\settings.json` — це звичайний файл JSON, і ви можете редагувати його вручну. Він містить
мову інтерфейсу, скільки резервних копій зберігати для кожного PATH і де востаннє стояло вікно.
Інструменти → Налаштування… змінює перші два.

Якщо файл узагалі не вдається прочитати — зламаний JSON або не текст — PathMaster **не
перезаписує його**. Він перейменовує файл на `settings.json.bad` (одна копія; наступний випадок її
замінює), стартує на типових значеннях і повідомляє про це діалогом. Усе, що у вас було, лишається
у файлі `.bad`.

Якщо ж хибне одне *значення* — код мови, невідомий цій версії, від'ємне число — до типового
значення повертається лише це налаштування, і лише в пам'яті, а **файл зберігає те, що ви
написали**, доки ви не зміните це саме налаштування в діалозі налаштувань. Поля, яких PathMaster
не знає, він не чіпає, і вони переживають кожен перезапис, як і порядок ключів.

## Чого PathMaster свідомо не робить

Кожен із цих пунктів — рішення, а не недогляд.

- **Він не вгадує помилки друку.** `C:\Python312` і `C:\Python313` — обидві цілком нормальні теки,
  і діагностика, яка зчиняла б через них тривогу, знецінила б усю решту діагностики. Він повідомляє
  те, у чому може бути певен: відсутні теки, відносні шляхи, записи в лапках, дублікати, порожні
  записи та об'єднаний PATH, довший за той, яким може скористатися `cmd.exe`.
- **Він ніколи не чіпає мережевих шляхів.** Запис на `\\сервер\ресурс` ніколи не перевіряється на
  існування й ніколи не позначається як відсутній: мертвий UNC-шлях блокує програму на 20–60
  секунд, і це неможливо скасувати, а програма, яка завмирає, гірша за програму, яка каже менше.
- **У ньому немає налаштування теми.** Він завжди користується вашими кольорами Windows і не
  задає власних.
- **Його не підписано** — за рішенням; див. [вище](#windows-покаже-попередження-і-це-очікувано).

Можливості, яких просто *ще* немає, живуть у трекері задач, а не в цьому переліку.

## Як перевіряються випуски

Автоматичних тестів інтерфейсу цієї програми немає, і в цьому README свідомо немає значка, який
стверджував би протилежне. Натомість є [контрольний список](docs/release-checklist.md): письмовий
сценарій кожного кроку, де для кожного названо точні слова, які має промовити NVDA, і який
особисто проходять на справжній NVDA перед кожним випуском.

**До кожного випуску долучається заповнена копія цього списку** — із назвою версії NVDA, з якою
його проходили, і з позначкою «пройдено», «провалено» або «пропущено» для кожного кроку.
Провалений крок блокує випуск. Для непідписаного файла цей записаний ручний прохід і є чесним
свідченням, якому можна довіряти, — а сценарій можна прочитати ще до того, як вирішувати, чи
довіряти.

Автоматичні перевірки теж виконуються на кожному випуску, і саме над опублікованим файлом, а не
над збіркою, що його зробила: він не повинен залежати від бібліотек Visual C++, має бути менший
за 40 МБ і мусить нести ту саму версію в теґу, у джерельному коді та у власних властивостях
виконуваного файла.
